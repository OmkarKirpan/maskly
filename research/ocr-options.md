# OCR engine options for dense UI screenshots

Resolves [#4](https://github.com/OmkarKirpan/maskly/issues/4). Researched 2026-10-03 against project docs, source code and PyPI metadata.

**Need (from the PRD):** offline OCR that returns each word's text and box (FR-3) for dense support-UI screenshots, called from a Python/FastAPI backend, on macOS Apple Silicon (dev/demo) and Windows (PRD "Platform" row lists both).

## Answer

Bake off **RapidOCR** and **Tesseract**. Both are pip-installable on macOS arm64 and Windows and both can produce word-level boxes. Apple Vision via `ocrmac` is likely good on screen text, but it only runs on macOS and its default Vision mode returns boxes per line, not per word.

## Shortlist for the bake-off (#8)

1. **RapidOCR (PP-OCRv6 small, ONNX Runtime).** It runs the same detector and recognizer as PaddleOCR, which should handle small, dense UI text better than Tesseract, but installs with plain pip on Mac and Windows and skips the PaddlePaddle framework.
2. **Tesseract 5 (`pytesseract`, `--psm 11`, 2x upscale, invert for dark mode).** Native word boxes, small, fast and cross-platform. It is the baseline the PRD already names; the open question is whether preprocessing gets it to acceptable accuracy.

Dropped: **PaddleOCR full** (same models as RapidOCR but more install friction, so test it only if RapidOCR's word grouping fails). **Apple Vision / ocrmac** (macOS only, and word boxes would need custom code; a good fallback if Windows is cut). **docTR** (heavy torch dependency and slow CPU defaults).

## Open items to check in the bake-off

- RapidOCR `word_results` for English: whole words or single characters? (**unconfirmed**) If characters, merge them into words at spaces.
- Tesseract accuracy on dark-mode and 11 to 13 px UI text after 2x upscaling: no primary-source numbers found.
- No high-trust public benchmark on dense UI screenshots was found for any engine. The 50-screenshot synthetic set in the PRD is the real test.
